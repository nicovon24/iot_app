**Bug found and fixed live during this session (unrelated to the gating work above):** `UsersService.create()` crashed with a 500 (`SyntaxError: Unexpected token 'h'`) — ThingsBoard's `GET /api/user/:id/activationLink` returns the activation URL as **raw plain text**, not JSON `{value: "..."}`, but the code unconditionally `JSON.parse`d the response body via the shared `parseJsonBody` helper. Pre-existing bug from Phase 2.2-02, surfaced by live-testing 9.2-02's Add User flow. Fixed by adding `ThingsboardClientService.requestText()` (a plain-text sibling to `request<T>()`, same auth/retry-on-401 contract) and switching `UsersService.create()` to use it for that one call. Any other TB endpoint found to return non-JSON should use `requestText()` too, rather than another one-off workaround.
