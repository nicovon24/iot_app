# 9.1-01 Summary: Design foundation, sidebar/header, Login split-screen

## What shipped

**Task 1 — Light glass design tokens, Inter font, dark-mode removal**
- `globals.css`: rewrote `:root` to the light glassmorphic token set (`--color-surface: #eef0f6`, `--color-surface-card: rgba(255,255,255,0.72)`, translucent `--color-border`), added `--gradient-accent-from/to` (#818cf8→#c084fc) + `--gradient-accent`, status gradients (`--gradient-ok/-danger/-info-from/to`), `--gradient-sidebar`, and repointed `--gradient-header-from/to` at the accent gradient. Deleted the entire `:root.dark` block — no dark variant exists anymore. Added `.glass-card` utility (blur(14px), translucent border, layered shadow) and `fadeUp`/`.animate-fade-up`.
- Kept `--color-navy-950/900/800` — still used by `Tooltip.tsx`, the sidebar's dashboard dropdown, and map markers as fixed dark constants, unrelated to the light/dark theme swap.
- `layout.tsx`: swapped `Nunito_Sans` for `Inter` (`next/font/google`, variable `--font-sans`, weights 400–800); removed the inline `<script>` that read `iot_theme` from `localStorage` and toggled the `dark` class pre-hydration (no longer needed, no dark mode to flash-prevent).
- Deleted `frontend/src/hooks/useTheme.ts`.
- `Sidebar.tsx`: removed the `useTheme` import/usage and the Moon/Sun `SidebarButton` entirely; kept the existing "Hide/Show labels" expand-collapse toggle and Log out button unchanged (functional, not touched).
- `providers.tsx`: stripped the two `dark:` Tailwind variants from the Toaster's error-toast classNames (only remaining `dark:` usage in the codebase).

**Task 2 — Sidebar + AppLayout restyle**
- `Sidebar.tsx` rail background changed from the old header-gradient to `var(--gradient-sidebar)` (dark purple/indigo radial); added a decorative blurred accent-gradient blob (`absolute -right-10 -top-10 h-40 w-40 blur-3xl opacity-30`) positioned behind the logo/nav/bottom-button groups (all three given `relative z-10` to stay above it).
- Active nav item: replaced the white-pill/`text-navy-950` swap with `background: var(--gradient-accent)` (inline style on the `motion.div` pill, since it's a runtime CSS variable) + `text-white`; inactive/`comingSoon` styling unchanged.
- `AppLayout.tsx`: no code changes needed — its header already read `--gradient-header-from/to` (now pointing at the accent gradient) and its shell background already read `bg-surface`/`--color-surface` (now the light `#eef0f6`), so both picked up the new look purely from the token change in Task 1.

**Task 3 — Login split-screen**
- Found the Login page was **already** a split-screen layout (left form / right decorative icon-grid panel) from prior work — no restructuring needed, only restyling:
  - Left form wrapped in `.glass-card` (was a bare unstyled container) + `.animate-fade-up`.
  - Input backgrounds changed from `bg-surface-card` to `bg-white/80` (avoids the input blending into the identically-colored parent glass card).
  - Primary submit button: `bg-accent` → `background: var(--gradient-accent)`.
  - Right decorative panel: `bg-accent` → `var(--gradient-accent)`; added `blur-2xl` to its two decorative white-opacity circles.
- No changes to `login()`/`ApiError` handling, form state, or validation.

## Verification
- `npx tsc --noEmit` in `frontend/` — clean after every task.
- `grep -r "dark:\|useTheme" frontend/src` — no matches.
- All 3 ACs met: no dark-mode toggle/`.dark` class/`.dark` CSS block anywhere; Sidebar/app shell match the gradient/glass direction; Login is a glass split-screen with auth logic unchanged.

## Deviations from plan
- None of substance. Task 3's plan anticipated possibly *building* a split-screen layout; the codebase already had one, so the task became a pure restyle (smaller than planned, same outcome).
