<objective>
## Goal
Build a reusable skeleton-loading component system and use it to replace the current bare `Spinner` loading states in `CountTileWidget`, `EntityListWidget`, and `AlarmsListWidget`; restyle the Dashboard page (stat tiles, list containers) to the new glass-card look established in 9.1-01, leaving the embedded fleet map untouched.

## Purpose
The user explicitly asked for improved loading UX (skeletons/animations) for widgets and the Dashboard, on top of the visual modernization ask. Building skeletons as shared primitives now means every widget that already reports `isLoading` (Devices/Assets/Admin lists, Alarms, stat tiles) gets the upgrade for free, including screens restyled later in 9.1-03.

## Output
- `components/Skeleton.tsx`: base `Skeleton` primitive + `StatTileSkeleton`/`TableRowsSkeleton` composed variants
- `CountTileWidget`, `EntityListWidget`, `AlarmsListWidget` use the new skeletons instead of `Spinner` on `isLoading`, restyled as glass cards
- `app/dashboard/page.tsx` restyled: glass-card stat tiles with gradient icon badges, glass-card list containers, map panel left exactly as-is
</objective>

    - Base `Skeleton` component: `{ className？: string; style?: React.CSSProperties }` props, renders a `<div>` with a pulsing/shimmer background (`bg-white/40` over the glass surface, or a CSS `@keyframes shimmer` gradient sweep — pick shimmer for a closer match to the "animation" ask: a horizontal gradient sweep using `background: linear-gradient(90deg, rgba(255,255,255,0.3) 25%, rgba(255,255,255,0.6) 37%, rgba(255,255,255,0.3) 63%); background-size: 400% 100%; animation: shimmer 1.4s ease infinite;`), `rounded-md` by default, size driven entirely by className/style passed in (no fixed dimensions on the base component).

    Avoid: adding a new animation/skeleton npm package (react-loading-skeleton etc.) — plain CSS + Tailwind covers this, keeping the dependency footprint the same as before.
