# 9.1-02 Summary: Skeleton system + Dashboard restyle

## What shipped

**Task 1 — Reusable Skeleton component system**
- New `components/Skeleton.tsx`: base `Skeleton` primitive (shimmer background via CSS `animate-shimmer`, size fully driven by `className`/`style`), plus `StatTileSkeleton` and `TableRowsSkeleton({ rows, columns })` composed variants.
- `globals.css`: added `@keyframes shimmer` + `.animate-shimmer` (400% background-size horizontal gradient sweep over translucent white), alongside the `fadeUp` keyframes from 9.1-01. No new npm dependency.

**Task 2 — Wired skeletons + glass restyle into shared widgets**
- `CountTileWidget`: now a `.glass-card`, gained an `accent?: 'ok' | 'danger' | 'info'` prop (default `'info'`) rendering a small gradient icon badge; loading state uses a targeted `<Skeleton className="h-7 w-12" />` for just the number (kept the label as real text rather than skeletoning it too, since the label is static and known immediately — a deviation from the plan's literal "StatTileSkeleton for the whole tile" but a better UX outcome; `StatTileSkeleton` still exists as an exported primitive for any future full-tile-loading case).
- `EntityListWidget`: loading branch replaced with `<TableRowsSkeleton rows={4} columns={4} />`; both card wrapper branches (titled/untitled) now use `.glass-card` instead of `border-border bg-surface-card`.
- `AlarmsListWidget`: loading branch replaced with `<TableRowsSkeleton rows={4} columns={5} />`; both wrapper branches use `.glass-card`; empty-state restyled to the "centered glass card + icon badge + headline" pattern from CONTEXT.md — a small `info`-gradient circular badge with a `BellOff` icon above the existing `emptyLabel` text.
- No prop-signature breaks — `accent` is optional, every existing call site (`app/dashboard`, `app/devices`, `app/assets`, `app/admin`, `app/alarms`) compiles unchanged.

**Task 3 — Dashboard restyle**
- `app/dashboard/page.tsx`: Devices/Assets tiles get `accent="info"` (cyan), Active Alarms tile gets `accent="danger"` (red) — per the mockup's stat-color convention. No structural/layout changes. `FleetMapWidget` usage untouched (same props, same `heightClassName="h-full"`) — map exclusion honored.

## Verification
- `npx tsc --noEmit` in `frontend/` — clean after every task.
- `grep -rn "Spinner" src/widgets/CountTileWidget.tsx src/widgets/EntityListWidget.tsx src/widgets/AlarmsListWidget.tsx` — no matches (Spinner import fully removed from all three).
- All 3 ACs met: skeleton system exists and matches the glass language; widgets show skeletons while loading and are glass cards; Dashboard uses accent gradients with the map panel provably untouched.

## Deviations from plan
- `CountTileWidget`'s loading state skeletons only the numeric value, not the label (plan described a full `StatTileSkeleton` swap) — the label text is static per-instance and already known at render time, so skeletoning it added visual noise without informational value. `StatTileSkeleton` remains exported and available if a future caller needs the full-tile version.

## Not yet done (by design — 9.1-03)
- Shared Dialog/Select restyle, Admin Miller-column panel, entity detail tabs, global Alarms page chrome.
- No interactive browser verification performed in this environment — `tsc --noEmit` + static review only; visual confirmation is the user's own via `npm run dev`.
