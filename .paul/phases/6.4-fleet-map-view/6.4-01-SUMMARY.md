# Phase 6.4 Plan 01: Fleet map view Summary

**The per-entity Map tab now shows an alarm-colored pin with a popup listing every telemetry key; a new "Maps" nav entry shows the whole fleet of real Devices on one map, with nearby pins clustered into circles.**

## Acceptance Criteria Results

| Criterion | Status | Notes |
|-----------|--------|-------|
| AC-1: Per-entity Map tab pin reflects alarm state and opens a rich popup | Pass | Verified against real Device `industrial-pump-005`: its one real alarm is `CLEARED_UNACK` (not active), so `hasActiveAlarm` correctly evaluates `false` → green pin; `GET /entities/:id/telemetry/latest` (no `keys` filter) confirmed returning all 13 real telemetry keys for the popup |
| AC-2: New fleet map nav entry shows every real Device with location on one map | Pass | `FleetMapWidget` iterates `useEntities('DEVICE')`, each `FleetMarker` checks `useTelemetryKeys` for `latitude`+`longitude` before rendering — Devices missing either key render `null` (verified via code review of the exact same key-presence logic already proven correct in 06-03's Map tab gating) |
| AC-3: "Details" button navigates to the entity detail page | Pass | `EntityMapMarker`'s button calls `useRouter().push(detailsHref)` with `detailsHref={\`/entities/${id}?type=DEVICE\`}` — same URL shape as `EntityListWidget`'s existing row navigation, `tsc --noEmit` confirms the shared prop contract type-checks in both `MapWidget` and `FleetMapWidget` call sites |
| AC-4: Nearby pins cluster into a numbered circle | Pass | `react-leaflet-cluster`'s `MarkerClusterGroup` (peer-compatible with the installed `react-leaflet@5.0.0`/`@react-leaflet/core@3.0.0`) wraps all `FleetMarker` elements; this is the standard `Leaflet.markercluster` library, the same clustering mechanism ThingsBoard itself uses — visual confirmation of the cluster circle/expand behavior deferred to the user's browser (no headless-browser tool in this environment, consistent with every prior Phase 6 plan) |

## Accomplishments

- `EntityMapMarker` is a genuinely shared component — the per-entity Map tab and the new fleet map render pixel-identical markers/popups, no divergent implementations to maintain
- `MapWidget.tsx` went from a dumb lat/lng/label renderer to fetching its own alarm+telemetry data, which is what let the fleet map reuse the exact same popup content without duplicating the telemetry-formatting logic
- First real use of `react-leaflet-cluster`/`Leaflet.markercluster` in this codebase, confirmed peer-compatible with the existing `react-leaflet@5` install from Phase 6

## Verification Method

No headless-browser tool available in this environment (same constraint as every Phase 6 plan). Verified via:
- `npx tsc --noEmit` — clean after both tasks
- Direct `curl` calls against the real backend (existing session token) confirming real alarm status (`CLEARED_UNACK`, correctly non-active) and all 13 real telemetry keys for `industrial-pump-005`
- `curl` against the Next.js dev server confirming `/map`, `/entities/{id}?type=DEVICE`, `/devices`, `/alarms` all render (200, no server-side crash) — regression check for Phase 6 pages plus the new page
- Final interactive visual confirmation (marker colors, popup scroll, cluster circle expand-on-zoom) deferred to the user's own browser check

### Summary

| Type | Count | Impact |

**1. [Scope addition] Map tile style toggle (default white/light) + barely-visible popup scrollbar**
- **Found during:** Live user feedback right after Task 1/2 verification, before UNIFY
- **Request:** The map should default to a white/grayscale basemap (not color), with a button to switch to color; the popup's telemetry-list scrollbar should barely be visible
- **Fix:** Added `frontend/src/lib/map-tiles.ts` (CartoDB Positron "light" vs OSM "color" tile configs) + `frontend/src/widgets/MapStyleToggle.tsx` (shared toggle button), wired into both `MapWidget` and `FleetMapWidget` with local `useState<MapTileStyle>('light')`; added `.map-popup-scroll` (invisible-at-rest, faint-on-hover scrollbar) to `globals.css` and applied it to `EntityMapMarker`'s telemetry list container
- **Files:** `frontend/src/lib/map-tiles.ts` (new), `frontend/src/widgets/MapStyleToggle.tsx` (new), `frontend/src/widgets/MapWidget.tsx`, `frontend/src/widgets/FleetMapWidget.tsx`, `frontend/src/widgets/EntityMapMarker.tsx`, `frontend/src/app/globals.css`
- **Verification:** `tsc --noEmit` clean; `curl` against the dev server confirmed `/map` and `/entities/{id}?type=DEVICE` still render (200) after the change; visual confirmation of the toggle/scrollbar behavior deferred to the user's browser, same constraint as the rest of this plan

The plan itself was executed with no other deviations. It anticipated centering the fleet map on "the average of all plotted Devices' coordinates, or a fixed fallback center" — implemented as the fixed fallback only (world view, zoom 2), since computing a live average would require lifting each `FleetMarker`'s async-loaded coordinates back up into the parent `FleetMapWidget`, a real complexity increase for a purely cosmetic initial framing. Logged as a decision, not a gap.
