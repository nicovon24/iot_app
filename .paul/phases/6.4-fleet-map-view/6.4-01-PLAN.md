<objective>
## Goal
The existing per-entity Map tab (Phase 6) gets a modernized marker whose color reflects the entity's alarm state, and a popup showing its full telemetry snapshot. A new "Maps" nav entry shows every real Device with location telemetry on one fleet-wide map, using the exact same marker/popup, with nearby pins clustered into a numbered circle (à la ThingsBoard) that expands on zoom/click.

## Purpose
Phase 6 proved the single-entity map works but left it visually minimal (default Leaflet pin, no alarm awareness) and entity-scoped only — an operator had no way to see the whole fleet's location/status at a glance. This phase makes the map tell the operator something at a glance (is this thing OK?) and adds the first cross-entity spatial view, mirroring the Global Alarms page's "look at everything, not just one entity" value from 06-03.

## Output
- `frontend/src/widgets/EntityMapMarker.tsx`: shared presentational marker (custom `L.divIcon`, colored by alarm state) + popup (name, full telemetry list with scroll, last report time, "Details" button)
- `frontend/src/widgets/MapWidget.tsx`: refactored to fetch its own alarm/telemetry data and render `EntityMapMarker` (was: raw lat/lng/label props + default Leaflet marker)
- `frontend/src/widgets/FleetMapWidget.tsx`: new — lists every real Device with `latitude`/`longitude` telemetry keys, clustered via `react-leaflet-cluster`
- `frontend/src/app/map/page.tsx`: new page rendering `FleetMapWidget`
- `frontend/src/lib/nav-items.ts`: new "Maps" nav entry pointing at `/map`
- `react-leaflet-cluster` added as a frontend dependency
</objective>

<acceptance_criteria>

## AC-1: Per-entity Map tab pin reflects alarm state and opens a rich popup
```gherkin
Given a real Device with `latitude`/`longitude` telemetry (the Map tab is enabled per Phase 6)
When the Map tab is open
Then the pin is colored green if the Device has no ACTIVE_UNACK/ACTIVE_ACK alarm, or red/amber if it has one; clicking the pin opens a popup showing the Device's name, ALL of its telemetry keys and current values (in a scrollable container if long), and its last report time (the most recent telemetry timestamp)
```

## AC-2: New fleet map nav entry shows every real Device with location on one map
```gherkin
Given real Devices exist, some with `latitude`/`longitude` telemetry keys and some without
When the user opens the new "Maps" nav item
Then only Devices with both `latitude` and `longitude` keys appear as pins on a single map, each using the same alarm-colored marker and popup as AC-1; Devices without location data do not appear at all (not an empty/error pin)
```

## AC-3: "Details" button navigates to the entity detail page
```gherkin
Given a marker's popup is open, on either the fleet map or the per-entity Map tab
When the "Details" button in the popup is clicked
Then the browser navigates to /entities/{id}?type=DEVICE for that specific Device
```

## AC-4: Nearby pins cluster into a numbered circle
```gherkin
Given the fleet map has multiple Devices whose coordinates are close together at the current zoom level
When the map renders at that zoom level
Then those pins are grouped into a single circle marker showing their count, and zooming in (or clicking the cluster) expands it into the individual pins
```
