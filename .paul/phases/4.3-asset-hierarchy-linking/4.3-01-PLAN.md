<objective>
## Goal
`POST /customers` accepts an optional `parentCustomerId` so a Customer can be created as a sub-customer of another Customer in the same request, instead of always being created at the root of the hierarchy.

## Purpose
ThingsBoard already supports native customer-parent hierarchies (used read-side since Phase 2.2 for `CustomerScopeGuard`'s `isDescendantCustomer` walk via `parentCustomerId`). This closes the write-side gap: today there is no way to create a Customer already nested under another one via this API — you'd have to create it flat and have no way to reparent it afterward.

## Output
- `CreateCustomerDto` gains an optional `parentCustomerId` field (validated as a TB id)
- `EntitiesService.createCustomer` passes it through to ThingsBoard's `POST /api/customer`
- `CustomersService.create` forwards it unchanged
</objective>

## AC-1: Customer created with a parent
```gherkin
Given a sysadmin session and an existing Customer "Test" (real TB id)
When POST /customers is called with { name: "Sub A", hierarchyLevels: [...], parentCustomerId: "<Test's id>" }

```

