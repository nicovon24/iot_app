<objective>
## Goal
`/entities/[id]?type=DEVICE|ASSET` renders a tabbed entity detail page. The Attributes tab shows a live-refreshable table of CLIENT/SERVER/SHARED scope attributes; the Telemetry tab lets the user pick a key and see its live value (WS) plus a historical line chart (REST, using the `agg`/`interval` params from Phase 2.1). Alarms and Map tabs render as placeholders in this plan — 06-03 wires them. Devices/Assets list rows (from 06-01) become clickable, navigating here.

## Purpose
This is the core "drill into an entity" experience the whole app exists to prove out — real live data (not TB's own UI) for any Device/Asset without hardcoded key lists. It's also the first real consumer of the WS telemetry client (`lib/ws-client.ts`) from a page component, and the first use of the `interval`/`agg` timeseries params Phase 2.1 built specifically for this widget (see ROADMAP.md Phase 2.1 note).

## Output
- `frontend/src/hooks/useEntityAttributes.ts`, `useEntityTelemetry.ts` (keys + latest + historical timeseries), `useLiveTelemetry.ts` (WS subscription wrapper)
- `frontend/src/widgets/ValueTileWidget.tsx`, `LineChartWidget.tsx` (Recharts), `AttributesTableWidget.tsx`
- `frontend/src/app/entities/[id]/page.tsx`: real tabbed detail page (replaces the `.gitkeep` placeholder), using HeroUI `Tabs`
- `EntityListWidget.tsx` gains row navigation; `devices/page.tsx`/`assets/page.tsx` wire it to `/entities/[id]?type=...`
- `recharts` added as a frontend dependency
</objective>

  <name>Task 1: Attributes + Telemetry hooks (REST + WS)</name>
  <files>frontend/src/hooks/useEntityAttributes.ts, frontend/src/hooks/useEntityTelemetry.ts, frontend/src/hooks/useLiveTelemetry.ts</files>
  <action>
    `useEntityAttributes(id, type)`: TanStack `useQuery`, query key `['attributes', id]`, fetches all 3 scopes in parallel (`Promise.all` of 3 `apiClient.get` calls to `/entities/:id/attributes?type=&scope=`), returns `{ CLIENT_SCOPE, SERVER_SCOPE, SHARED_SCOPE }` grouped by scope.
    `useEntityTelemetry(id, type)`: exposes three pieces — `useKeys()` (`useQuery` on `/entities/:id/telemetry/keys`), `useLatest(keys?)` (`useQuery` on `/entities/:id/telemetry/latest`), and `useHistory(key, { startTs, endTs, agg, interval })` (`useQuery` on `/entities/:id/telemetry/timeseries`, enabled only when `key` is truthy). Default the history window to the last 1 hour (`endTs = Date.now()`, `startTs = endTs - 3600_000`) with `agg=AVG&interval=300000` (5-min buckets) matching AC-3, matching Phase 2.1's intended usage (see ROADMAP.md note under Phase 2.1).
    `useLiveTelemetry(target: SubscribeTarget, onFrame)`: thin `useEffect` wrapper around `createWsClient('telemetry').subscribe(target, onFrame)` from `lib/ws-client.ts` — creates the client on mount, subscribes, and returns the cleanup function from `subscribe()` plus `client.close()` in the `useEffect` cleanup, so unmounting always tears down both the subscription and the socket (addresses AC-5's leak requirement).
    Avoid: re-implementing WS connection logic outside `lib/ws-client.ts` — this hook only orchestrates it inside React's lifecycle.
  </action>
  <verify>With the backend running and a real session token, call each hook's underlying query/WS logic against a real Device id (temporary script, delete after) — confirm attributes/keys/latest/history return real shapes and a WS frame arrives for a subscribed key.</verify>
