<objective>
## Goal
A running NestJS+Fastify backend that logs into ThingsBoard, caches its JWT in Redis, and exposes its own `/auth/login` / `/auth/logout` session — with Swagger live from the first endpoint.

## Purpose
Every later module (entities, attributes, telemetry, alarms, clients) depends on an authenticated ThingsBoard client. This plan lays that foundation once, correctly, per PROJECT.md's constraint that ThingsBoard credentials never reach the frontend.

## Output
- `backend/src/config/` — env validation (zod) + typed config service
- `backend/src/thingsboard/` — client service (login/refresh/generic request) backed by Redis JWT cache
- `backend/src/auth/` — app-level login/logout module
- `backend/src/main.ts`, `backend/src/app.module.ts` wired together with Swagger
</objective>

## AC-1: Config validation
```gherkin
Given backend/.env is missing THINGSBOARD_URL
When the app boots
Then it fails fast with a clear validation error, not a runtime crash later
```

## AC-2: ThingsBoard login + Redis cache
```gherkin
Given valid ThingsBoard credentials in env
When ThingsboardClientService.getToken() is called twice in a row
Then the second call returns the Redis-cached token without a new login request to ThingsBoard
```

## AC-3: App-level session
```gherkin
Given a client calls POST /auth/login with valid credentials
When the backend authenticates against ThingsBoard successfully
Then it returns an app session (not the raw ThingsBoard JWT) and the endpoint is documented in Swagger
```

    - `config.service.ts`: parses `process.env` through the schema at module init, throws on failure (fail-fast, satisfies AC-1), exposes typed getters
    - `config.module.ts`: NestJS `@Global()` module exporting ConfigService
    - `main.ts`: bootstrap with `NestFactory.create(AppModule, new FastifyAdapter())`, register `@fastify/swagger` + `@fastify/swagger-ui` at `/api/docs`, `app.listen(config.port)`
    - `app.module.ts`: imports ConfigModule, ThingsboardModule, AuthModule
    Avoid: reading `process.env` directly anywhere outside config.service.ts — every other module consumes ConfigService.
  </action>
  <verify>`npm run start:dev` boots without throwing when .env has all required vars; boots with a clear thrown error when THINGSBOARD_URL is unset</verify>
  <done>AC-1 satisfied</done>
</task>

<task type="auto">
  <name>Task 2: ThingsBoard client service with Redis-cached JWT</name>
  <files>backend/src/thingsboard/thingsboard.module.ts, backend/src/thingsboard/thingsboard-client.service.ts, backend/src/thingsboard/redis.service.ts</files>
  <action>
    - `redis.service.ts`: thin wrapper around a Redis client (using `ws`'s sibling lib is wrong — use a minimal `redis`/`ioredis`-free approach only if a client dependency exists; otherwise add `ioredis` to package.json dependencies before using it), `get(key)`, `set(key, value, ttlSeconds)`
    - `thingsboard-client.service.ts`:
      - `login()`: POST `{THINGSBOARD_URL}/api/auth/login` with username/password, returns `TbLoginResponse`
      - `getToken()`: checks Redis key `tb:jwt` first; on miss, calls `login()`, stores token in Redis with TTL slightly under ThingsBoard's own expiry (decode JWT `exp` claim, don't hardcode a TTL guess)
      - `request<T>(method, path, options)`: generic authenticated HTTP helper that injects `X-Authorization: Bearer {token}`, used by every later module — this is the ONLY place that talks to ThingsBoard's HTTP API directly
    - `thingsboard.module.ts`: exports `ThingsboardClientService`
    Avoid: any other module constructing its own HTTP client toward ThingsBoard — everything goes through this service (per PROJECT.md constraint).
  </action>
  <verify>Manual: call `getToken()` twice via a temporary test endpoint or unit test; second call does not hit ThingsBoard (mock/spy on the login HTTP call, assert called once)</verify>
  <done>AC-2 satisfied</done>
</task>

<task type="auto">
  <name>Task 3: App-level auth module (login/logout) + Swagger docs</name>
  <files>backend/src/auth/auth.module.ts, backend/src/auth/auth.controller.ts, backend/src/auth/auth.service.ts, backend/src/auth/dto/login.dto.ts</files>
  <action>
    - `login.dto.ts`: `LoginDto { username: string; password: string }` decorated with `class-validator` + `@ApiProperty` for Swagger
    - `auth.service.ts`: `login(dto)` delegates credential check to `ThingsboardClientService` (reuse the same TB login call — for V1 there's one shared TB user, not per-operator TB accounts) and returns an app session marker (opaque token or cookie), `logout()` clears it
    - `auth.controller.ts`: `POST /auth/login` (returns app session, never the raw TB JWT), `POST /auth/logout`, both with `@ApiTags('auth')` and full Swagger response schemas
    Avoid: returning `TbLoginResponse.token` directly to the caller — that violates the "TB credentials never reach the frontend" constraint from PROJECT.md.
  </action>
  <verify>Swagger UI at /api/docs shows POST /auth/login and /auth/logout with request/response schemas and "Try it out" works against a real or mocked ThingsBoard instance</verify>
  <done>AC-3 satisfied</done>
</task>
