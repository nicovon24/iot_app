<objective>
## Goal
The dashboard builder offers a multi-turn assistant to create or edit dashboards, with provider settings, conversation history, draft preview, and explicit save using IoTArg's visual language.

## Purpose

The current uncommitted panel is a one-prompt dialog. The user wants a FaroDocs-like conversation workflow with IoTArg's typography, colors, ruled layout, and dashboard canvas.

## Output

Integrated assistant UI and browser-verified creation/revision flow.
</objective>

<acceptance_criteria>

## AC-1: Settings

Given a signed-in user, when they configure several provider/model/key connections and daily request/response-token limits, then the UI shows masked configured states and remaining requests, lets them select a connection for the chat, and supports independent replace/delete without revealing secrets.

## AC-2: Conversation

Given a configured connection, when the user asks for a dashboard then follows up with a revision, the chat shows both turns, loading/error states, and the latest draft. Conversation history is private and reopenable after login.

## AC-3: Preview and save

Given a generated draft for a new or existing dashboard, when the user reviews it, then widgets appear in the existing editable canvas with a summary of added, changed, moved, and removed widgets. The user can edit or discard it and must explicitly save; no provider response writes a dashboard by itself.

## AC-4: Visual and access checks

Given desktop and mobile viewports and a READER account, then the assistant fits the IoTArg design system, works with keyboard focus, and is unavailable to READER accounts.
</acceptance_criteria>
