<objective>
## Goal
Users choose an allowed ThingsBoard instance at login and all REST, WebSocket, and app-owned metadata remain scoped to that instance.

## Purpose

The current uncommitted login form accepts a URL, but the upstream telemetry WebSocket still connects to the fixed server URL. The app must not mix data or credentials between instances.

## Output

Completed instance-aware authentication, metadata scoping, and a reduced environment contract.
</objective>

<acceptance_criteria>

## AC-1: Instance choice

Given two configured ThingsBoard origins, when a user signs in to either one, then authentication and subsequent REST calls use only that origin. An unlisted or malformed origin is rejected before credentials are sent. Private or local origins require an explicit development configuration; production origins require HTTPS.

## AC-2: Data isolation

Given users and entities from different instances, when either user lists dashboards or receives telemetry, then no records or events from the other instance appear. Existing metadata is assigned to the former configured default origin through a compatible migration.

## AC-3: Environment contract

Given end-user authentication and upstream WebSockets work without a service account, when the backend starts, then THINGSBOARD_USERNAME and THINGSBOARD_PASSWORD are no longer required or used. DATABASE_URL, REDIS_URL, FRONTEND_URL, PORT, the approved ThingsBoard origins, and AI_CREDENTIAL_ENCRYPTION_KEY remain documented according to their real use.
</acceptance_criteria>
