# Fleet table intent

## Goal

An explicit request for one table containing all sensors produces one table of latest readings, with every visible device reachable and no cards added by the model.

## Acceptance criteria

1. The assistant's draft contract supports an all-device entity table and telemetry columns.
2. For an explicit all-sensors table request, the backend returns exactly one valid table even if the model proposes cards. Unspecified columns use the telemetry wildcard.
3. The preview states its rows, columns, and page size before applying the draft.
4. A fleet table can page through all visible devices, including while previewing in edit mode; each page fetches telemetry only for its rows.
5. Dashboard writes remain explicit, and existing user, instance, and provider boundaries remain intact.

## Verification

Run backend and frontend tests, lint, typecheck, builds, and a Playwright CLI flow with a mocked 25-device catalog. Review the diff and leave unrelated workspace changes untouched.
