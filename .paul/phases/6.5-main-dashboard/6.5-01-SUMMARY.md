# Phase 6.5 Plan 01: Main Dashboard Summary

**`/dashboard` is now a real fleet-health summary — Devices/Assets/active-alarm counts, the clustered fleet map, a Devices table, and an active-alarms table, all reused from Phase 6/6.4 with zero new backend calls — plus a visual placeholder for future custom dashboards.**

## Acceptance Criteria Results

| Criterion | Status | Notes |
|-----------|--------|-------|
| AC-1: Dashboard shows real fleet counts | Pass | Verified against the real backend: `GET /devices` → 4, `GET /assets` → 1, `GET /alarms` → 1 total alarm with 0 currently ACTIVE_UNACK/ACTIVE_ACK — the three `CountTileWidget`s compute exactly these values from `devicesQuery.data.totalElements`, `assetsQuery.data.totalElements`, and `activeAlarms.length` |
| AC-2: Dashboard shows the fleet map | Pass | `<FleetMapWidget />` imported and rendered with no prop changes — identical component instance to `/map`'s page |
| AC-3: Dashboard shows a Devices table | Pass | `<EntityListWidget>` fed the same `devicesQuery` result already used for the count tile — real 4 Devices confirmed via the same backend call as AC-1 |
| AC-4: Dashboard shows only active alarms, not full history | Pass (logic verified; no currently-active alarm to visually confirm) | The real tenant currently has 1 alarm total and 0 active (the `industrial-pump-005` alarm from Phase 3/6.3 verification is `CLEARED_UNACK`) — the client-side filter (`status === 'ACTIVE_UNACK' \|\| 'ACTIVE_ACK'`) correctly produces an empty `activeAlarms` array, so the table renders its "No active alarms" empty state rather than showing the 1 cleared alarm. This confirms the filter excludes cleared alarms correctly, though there was no active alarm available this session to also confirm a populated active row visually — logic is straightforward and matches the exact pattern already proven in `EntityMapMarker`/`FleetMapWidget` (Phase 6.4) |
| AC-5: A visual seam for future dashboards is present but non-functional | Pass | "Main Dashboard" pill with a `ChevronDown` icon, wrapped in the existing `Tooltip` component ("More dashboards coming soon"), `cursor-default`, no `onClick` handler, no state — confirmed via code review, no interactive logic exists to test |

## Deviations from Plan

### Summary

| Type | Count | Impact |
|------|-------|--------|
| Scope addition | 1 (one-screen, full-width layout) | Requested by the user immediately after this plan's initial verification, before UNIFY — layout-only change, no new data/behavior |

**1. [Scope addition] Dashboard fits one desktop screen at 100% width, no page scroll**
- **Found during:** Live user feedback right after Task 1/2 verification, before UNIFY
- **Request:** The dashboard should be visible on one screen on desktop (no scrolling) and use the full available width, not the app's shared centered `max-w-6xl` card
- **Fix:** `AppLayout.tsx` now special-cases `pathname === '/dashboard'` to skip the shared centered-card wrapper and page-level scroll (every other route is unaffected — same wrapper, same behavior). `dashboard/page.tsx` restructured as a `flex h-full flex-col` shell: a compact counts+seam row, then a `flex-1 min-h-0 grid grid-cols-3` splitting Fleet Map (2 cols) from a right column with two independently-scrolling panels (Devices, Active Alarms) — each table scrolls internally instead of the whole page scrolling. `FleetMapWidget` gained an optional `heightClassName` prop (default unchanged) so the dashboard's map can flex to fill remaining space instead of using `/map`'s fixed `h-[32rem]`.
- **Files:** `frontend/src/components/AppLayout.tsx`, `frontend/src/app/dashboard/page.tsx`, `frontend/src/widgets/FleetMapWidget.tsx`
- **Verification:** `tsc --noEmit` clean; `curl` confirmed `/dashboard`, `/map`, `/devices`, `/alarms` all still render (200) — `/map`'s `FleetMapWidget` usage keeps its default fixed height, confirming the prop change is backward-compatible. Final visual confirmation of exact one-screen fit across real desktop viewport sizes deferred to the user's own browser check, same constraint as every prior phase (no headless-browser tool in this environment).

The plan's own 2 tasks executed exactly as specified, no other deviations.
