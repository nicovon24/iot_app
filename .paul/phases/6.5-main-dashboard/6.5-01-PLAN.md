<objective>
## Goal
Replace `/dashboard`'s `ComingSoon` placeholder with a real summary view: Devices/Assets/active-alarms counts, the fleet map, a Devices table, and an active-alarms table — all composed from existing Phase 6/6.4 pieces — plus a non-functional visual seam that anticipates future (V2/V3) dashboards.

## Purpose
The Dashboard is the sidebar's first nav item and has been a placeholder since Phase 5. The user explicitly required this before Phase 7: an operator landing on the app should immediately see fleet health (counts, map, what needs attention) without navigating to `/devices`, `/map`, and `/alarms` separately. This is pure composition — no new data model, no new backend — proving out that Phase 6/6.4's components are genuinely reusable building blocks.

## Output
- `frontend/src/widgets/CountTileWidget.tsx`: new small presentational stat tile (label + value), distinct from the telemetry-shaped `ValueTileWidget`
- `frontend/src/app/dashboard/page.tsx`: real dashboard page — counts row, dashboard-name seam, fleet map, Devices table, active-alarms table
</objective>

  <action>
    Create `CountTileWidget.tsx`: a `'use client'` presentational component, `CountTileWidget({ label, value, isLoading }: { label: string; value: number; isLoading?: boolean })`. Render a `bg-surface-card border-border rounded-xl shadow-sm` tile (same visual family as `ValueTileWidget`'s tile, but simpler — no `ts`/`unit`/change-animation, since a count isn't telemetry): a large `text-heading` number (or a `Spinner` if `isLoading`) and a `text-muted uppercase text-xs` label underneath.     Create `frontend/src/app/dashboard/page.tsx` (replacing the `ComingSoon` placeholder) as a `'use client'` component. Fetch: `useEntities('DEVICE')`, `useEntities('ASSET')`, and `useGlobalAlarms({})` (no filter — the backend's `status` query param only accepts one value, and we need both `ACTIVE_UNACK` and `ACTIVE_ACK`). Compute `activeAlarms = (alarmsQuery.data?.data ?? []).filter(a => a.status === 'ACTIVE_UNACK' || a.status === 'ACTIVE_ACK')`. Render a page heading ("Dashboard") plus, next to it, a non-interactive "future dashboards" seam: a small pill/button styled like `EntityListWidget`'s row-action buttons (rounded, bordered, `text-body`) reading "Main Dashboard" with a `ChevronDown` (`lucide-react`) icon, wrapped in the existing `components/Tooltip.tsx` with the label "More dashboards coming soon" — `cursor-default`, `onClick` is a no-op (or omitted entirely), no dropdown menu, no state. Below the heading, render three `CountTileWidget`s in a flex/grid row: Devices (`devicesQuery.data?.totalElements ?? 0`), Assets (`assetsQuery.data?.totalElements ?? 0`), Active Alarms (`activeAlarms.length`), each `isLoading` wired to its respective query's `isLoading`.
    Avoid: fetching Customers count (explicitly out of scope per discussion — no simple existing customer-listing pattern to reuse); building any real dashboard-switching logic behind the "Main Dashboard" seam — it must stay purely visual.
