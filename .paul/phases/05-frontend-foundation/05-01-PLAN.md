<objective>
## Goal
`frontend/` becomes a running Next.js (App Router, TypeScript) app styled with Tailwind CSS + HeroUI, with a base `AppLayout` (sidebar nav: Devices, Assets, Alarms, Dashboard) rendering around every page.

## Purpose
Phase 5 is the foundation every later frontend phase (6: entity views, 7: wizard UI) builds on top of. Today `frontend/` is empty placeholder folders only (`src/components/.gitkeep` etc, no `package.json`) — this plan makes it a real, runnable app for the first time.

## Output
- `frontend/package.json` with Next.js, Tailwind, HeroUI, and their peer deps; wired into the existing root npm workspace
- App Router structure: `src/app/layout.tsx` (root layout wrapping `AppLayout` + HeroUI provider), `src/app/page.tsx` (placeholder home), `src/app/globals.css` (Tailwind directives + theme tokens), `src/app/providers.tsx`
- `src/components/AppLayout.tsx` + `src/components/Sidebar.tsx`: dark-navy sidebar with the full nav item list (4 active links + 3 future items shown disabled/hidden per role, see Design below)
- A "modern ThingsBoard-style" dark navy + electric-blue visual identity, expressed as reusable Tailwind theme tokens (not one-off hardcoded colors), so Phase 6/7 can reuse them without redefining the palette
- Dev server runs and renders the layout with working nav links

## Design
**Visual direction:** dark navy + electric blue, modern industrial-dashboard look (in the spirit of Grafana/ThingsBoard PE/Vercel dashboards, not a literal clone) — content area light/neutral for data-table legibility, sidebar dark for contrast and wayfinding.

**Color tokens** (define in `globals.css` as CSS custom properties, then reference from Tailwind via `theme.extend.colors` — never hardcode hex values directly in component files):
- `--color-navy-950: #0b1220` — sidebar background
- `--color-navy-900: #0f172a` — sidebar hover/active row background
- `--color-accent: #2563eb` — primary electric-blue accent (active nav indicator, primary buttons, links)
- `--color-accent-soft: #38BDF8` — secondary cyan accent (badges, highlights, chart accents in later phases)
- `--color-surface: #f8fafc` — main content background
- `--color-surface-card: #ffffff` — card/table backgrounds
- `--color-border: #e2e8f0` — content-area borders
- Text: near-white on navy (`#e2e8f0`), slate-800 on light surfaces

**Full navbar item list** (the complete system nav, not just this plan's scope — captures where every item routes to and when it goes live):

| Label (ES) | Route | Lands in | Visible/enabled in this plan? |
|---|---|---|---|
| Panel | `/dashboard` | Phase 5 (placeholder) → Phase 6 (real) | Yes, active |
| Dispositivos | `/devices` | Phase 6 | Yes, active (link works, page 404s until Phase 6) |
| Activos | `/assets` | Phase 6 | Yes, active |
| Alarmas | `/alarms` | Phase 6 | Yes, active |
| Clientes | `/clients` | Phase 7 (wizard UI) | Rendered but disabled (grayed, non-clickable, small "próximamente" affordance) — sysadmin-only when it lands |
| Usuarios | `/users` | V2 (backend already exists, Phase 2.2) | Rendered but disabled — sysadmin-only when it lands |
| Configuración | `/settings` | V2 | Rendered but disabled |

Disabled items exist in the `Sidebar` nav-items array now (as data, with a `comingSoon: true` flag) so Phase 6/7 only need to flip the flag and add the route — not restructure the sidebar. This is the "scale further in the future" requirement: the nav is data-driven from one array, not hardcoded JSX per link.
