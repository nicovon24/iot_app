# 15-01 — Isolated product demo

## Acceptance

- A visitor can enter from the login page with **Ingresar como demo**, without credentials or a running backend.
- The normal navigation shows representative simulated customers, assets, devices, alarms, telemetry, maps, and a saved dashboard.
- The dashboard assistant accepts prompts, offers a preview, and supports applying and saving simulated drafts without an LLM key.
- Demo reads and writes stay in browser session storage. No demo API or WebSocket request reaches the production backend; unsupported actions fail explicitly.
- A visible demo label identifies simulated data. Leaving demo clears its state and returns to login; real login remains unchanged.

## Implementation

1. Add a dedicated demo session marker and enter/leave actions.
2. Route the existing API and WebSocket clients to deterministic demo data when the marker is active.
3. Seed a small coherent fleet, dashboard, and assistant conversation store; support dashboard edits in session storage.
4. Add login entry, demo label, and assistant copy that makes simulation explicit.
5. Verify isolation and interactions with unit and browser checks, then review the diff.

## Constraints

- No ThingsBoard entity is persisted locally in production storage.
- Demo credentials, provider keys, and simulated conversations never leave the browser.
- Existing real-session behavior must remain unchanged.
