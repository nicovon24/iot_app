<objective>
## Goal
Three of the five widgets the user asked for, each added as a config flag on an existing widget type rather than a new widget type: a `'BAR'` style on the gauge (progress bar), a `stacked` flag on bar-chart, and a `sparkline` flag on value-tile.

## Purpose
These three don't need a new datasource shape or a new registry entry — they're presentation variants of data the existing types already fetch (gauge already has a `style` enum for exactly this reason; bar-chart already fetches per-entity series; value-tile can reuse the same dual-hook pattern ScatterCell already uses). Building them as flags instead of new types means each costs 2 touchpoints instead of the ~8 a new widget type requires (registry entry both sides, renderer switch case, cell component, WidgetPreview case, EntityWidgetConfig fields, config-panel wiring).

## Output
- Gauge `style` enum gains `'BAR'`, `GaugeWidget.tsx` gains a `Bar` rendering branch
- Bar-chart config gains `stacked?: boolean`, `MultiSeriesBarChartWidget` renders grouped or stacked bars accordingly, config panel shows the checkbox only for ALL-scope bar charts
- Value-tile config gains `sparkline?: boolean` (SINGLE scope only), `ValueTileWidget` renders a small trend line when set and history data is available, falling back to the plain tile when there's no history
</objective>

## AC-1: Gauge progress-bar style
```gherkin
Given a gauge widget with config `{ style: 'BAR', min: 0, max: 100 }` and a current value of 65
When it renders
Then it shows a horizontal track with a filled portion covering 65% of its width, consistent with
  the existing DIAL/THERMOMETER/RADIAL visual language (same label/value/timestamp footer)

Given the config panel's gauge style selector
When opened
Then "Progress Bar" appears as a fourth option alongside Dial/Thermometer/Radial
```

## AC-2: Stacked bar chart
```gherkin
Given a bar-chart widget with entityScope: 'ALL' and config `{ stacked: true }`
When it renders with 3 entities reporting a key
Then all 3 series render as one stacked bar per timestamp bucket (recharts stackId) instead of
  3 grouped bars per bucket

Given the same widget with `stacked: false` or omitted
Then bars render grouped exactly as they do today (no behavior change from before this plan)

Given a bar-chart widget with a SINGLE entity (not ALL scope)
When its config panel is opened
Then no "stacked" checkbox is shown — stacking one series is a no-op and the control would be
  confusing there
```

## AC-3: Sparkline value-tile
```gherkin
Given a value-tile widget with SINGLE scope and config `{ sparkline: true }`, on an entity that
  has telemetry history for the configured key
When it renders
Then it shows the normal label/value/timestamp plus a small trend line built from recent history

Given the same config but the entity has no history for that key (new device, or the key has
  never reported before)
Then it falls back to the plain tile layout — no empty/broken chart area

Given a value-tile widget with entityScope: 'ALL' (regardless of the sparkline flag)
When its config panel is opened
Then no "sparkline" checkbox is shown — sparkline is gated to SINGLE scope only (ALL-scope would
  fire up to MAX_TILES history requests per render)
```
