<objective>
## Goal
A new "Admin" nav section where a user picks a Client (or drills into a sub-client via breadcrumbs), sees that Client's Asset hierarchy as a drillable tree, and sees/manages the real Devices linked to whichever node (Client or Asset) is currently selected. Also: remove the "Create Client" / "Add Asset" buttons from their current homes on `/clients` and `/assets`, since creation now happens from this panel instead.

## Purpose
Closes the user's explicit ask this session: consolidate Client/Asset/Device hierarchy management into one admin view with breadcrumb navigation, instead of scattered create buttons on separate list pages. Built entirely on top of 08-01's new backend endpoints (Contains-relation reads, Device link/unlink, Asset update) — no further backend changes.

## Output
- `frontend/src/lib/nav-items.ts`: new "Admin" entry
- `frontend/src/app/admin/page.tsx`: the 3-panel admin view
- New hooks: `useCustomerChildren`, `useAssetChildren`, `usePatchAsset`, `useLinkDevice`, `useUnlinkDevice`
- New widgets: `AdminBreadcrumbs` (shared breadcrumb trail), `AdminAssetPanel` (Asset tree + add/edit/delete), `AdminDevicePanel` (linked Devices + assign/unassign)
- `frontend/src/app/clients/page.tsx` / `assets/page.tsx`: "Create Client" / "Add Asset" buttons removed (list + existing row actions stay)
</objective>

<acceptance_criteria>

## AC-1: Admin nav entry and breadcrumb-navigable Customer column
```gherkin
Given the user opens /admin from the new "Admin" nav item
When the page loads
Then a Customers column shows root Customers (no parentCustomerId); clicking one that has sub-customers drills into them with a breadcrumb trail back to root, and clicking a Customer with no sub-customers selects it as the active Client for the other two columns
```

## AC-2: Asset column reflects the selected Client's real Contains tree
```gherkin
Given a Client is selected (or drilled into via breadcrumbs)
When the Asset column loads
Then it shows that Client's level-0 Assets (via GET /customers/:id/children); clicking an Asset drills into its own children (via GET /assets/:id/children) with its own breadcrumb trail, and the clicked Asset becomes the active node for the Device column
```

## AC-3: Device column shows Devices linked to the active node, with assign/unassign only
```gherkin
Given a Client or Asset is the currently active (deepest-selected) node
When the Device column loads
Then it shows real Devices linked via a Contains relation from that node (empty if the active node is a bare Customer, since device linking requires an Asset); an "Assign" action opens a picker over unlinked real Devices and creates the relation; each linked Device row has only an "Unassign" action — no edit, no delete-the-device
```

## AC-4: Add/delete Customer and Add/delete/edit Asset from the panel
```gherkin
Given the admin panel is open
When the user adds a Customer (reusing the Phase 7 wizard, pre-scoped as a sub-customer of whichever Customer is currently drilled into, or top-level at root), deletes a Customer/Asset (reusing Phase 7's ConfirmDialog + existing DELETE endpoints), or edits an Asset's name/type/label (new inline or modal form wired to PATCH /assets/:id)
Then each action succeeds against the real backend and the relevant column refetches to show the change
```

## AC-5: Create buttons removed from their old locations
```gherkin
Given /clients and /assets are loaded
When the page renders
Then neither page shows a "Create Client" / "Add Asset" button anymore — both pages still list their entities with existing row actions (Delete, and /assets' row-click-to-detail), creation now only happens from /admin
```
